# Terminal-Motion-Engine — `termo` 2.0

Play GIFs and videos **in the terminal** as ASCII / ANSI art — with sound, at the
source frame rate (60 fps and up), without flicker.

`termo` 2.0 is a single Go binary. It replaces the old `jp2a` + bash scripts
(still available in [`legacy/`](legacy/)): no more pre-splitting videos into
frame folders, no more screen clearing between frames.

```sh
termo video.mp4
```

## What's new in 2.0

- **Plays files directly** — any GIF, video or picture ffmpeg can read.
- **Audio** — the sound track plays in sync (PulseAudio / PipeWire / ALSA / ffplay).
- **Smooth** — only the cells that changed are written, inside a synchronized
  update, in one write per frame. No `clear`, no tearing, no blinking.
  Turning a 1080p60 frame into a 240×67 grid takes 0.2–5 ms depending on the mode
  and dither, against a 16.7 ms budget (`termo bench` measures it on your machine).
- **Five render modes** — half blocks, quadrants, sextants, braille, ASCII (9 character ramps or your own).
- **Palettes** — truecolor, 1–256 colors, 21 named palettes (gameboy, pico8, c64, nord…),
  palettes generated by color theory (monochromatic, analogous, complementary,
  split-complementary, triadic, tetradic, square, hexadic, hue-shift, golden, rainbow),
  adaptive palettes computed from the picture, and fully custom ones.
- **Dithering** — 18 algorithms: Bayer 2/4/8, blue noise, white noise, film grain,
  halftone, line screens, Floyd–Steinberg, Atkinson, JJN, Stucki, Burkes, Sierra ×3.
- **Randomize** — one key rolls a whole new look; another rolls just the palette; undo brings the last one back.
- **Presets** — save, load, edit, rename and delete looks, from the menu or the command line.
- **A real TUI** — HUD, settings popup, palette editor, file browser; everything works
  with the keyboard *and* the mouse (click, drag, wheel, right-click, double-click).

## Install

Requirements: **Go 1.26+** to build, **ffmpeg** (with `ffprobe`) at runtime.
For sound, any one of `pacat`, `pw-cat`, `aplay` or `ffplay`. Linux and macOS.

```sh
git clone https://github.com/Szmelc-INC/Terminal-Motion-Engine
cd Terminal-Motion-Engine
make install          # builds and copies ./termo to ~/.local/bin
# or just: go build -o termo ./cmd/termo
```

A truecolor terminal is recommended (kitty, ghostty, alacritty, foot, wezterm, iTerm2…).
256- and 16-color terminals work too: the picture is quantized and dithered to what
the terminal can show (`--depth 8` / `--depth 4` forces it).

## Usage

```sh
termo clip.mp4                       # play
termo                                # no file: open the file browser
termo a.gif b.mp4 c.webm             # playlist (n / N to switch)
termo -m braille -p matrix clip.mp4  # pick a look up front
termo -P gameboy clip.mp4            # start from a preset
termo -r clip.mp4                    # start with a random look
termo -p harmony --scheme triadic --hue 20 -c 6 -d halftone clip.mp4
termo --custom '#1a1c2c,#5d275d,#ef7d57,#f4f4f4' -d atkinson clip.mp4

termo snap --at 12.5 --size 120x40 clip.mp4 > frame.ans   # one frame as ANSI text
termo bench --all clip.mp4           # how fast is every mode on this machine
termo info clip.mp4
termo palettes                       # named palettes and color schemes
termo options                        # every option with its allowed values
termo presets list | show NAME | save NAME [look options] | edit NAME [options] | rename OLD NEW | rm NAME
```

Every setting in the menu is also a command-line flag (`termo options` lists them all).

## Keys

| Key | Action |
| --- | --- |
| `Space` / `k` | play / pause |
| `←` `→` · `Shift`+`←` `→` | seek 5 s · 30 s |
| `,` `.` | previous / next frame |
| `0`–`9` · `Home` | jump to 0–90 % · start |
| `↑` `↓` · `m` | volume · mute |
| `[` `]` · `l` | speed · loop |
| **`r`** | **randomize the whole look** |
| `R` | randomize the palette only |
| `u` | undo the last change |
| **`Tab`** / `s` / `F2` | **settings menu** |
| `p` `P` | next / previous preset |
| `Ctrl+S` | save the current look as a preset |
| `v` `d` `c` `a` (Shift = back) | cycle mode / dither / palette / charset |
| `-` `=` | fewer / more palette colors |
| `f` `x` `y` `e` `i` | fit · flip X · flip Y · edges · invert |
| `h` · `g` | HUD auto/on/off · performance stats |
| `o` · `n` `N` | open file · next / previous file |
| `?` / `F1` | help |
| `q` / `Ctrl+C` | quit |

**Mouse:** click the picture to pause, right-click for the menu, middle-click to
randomize, wheel for volume. Drag the seek bar and every slider, click or scroll the
HUD buttons to cycle mode / dither / palette, drag the settings window by its title bar.

### Settings menu

`Tab` opens a popup with seven tabs (switch with `Tab` or `1`–`7`, or click):

- **Render / Color / Dither / Adjust / Playback** — every option; `↑↓` to select,
  `←→` to change (`Shift` for bigger steps), `Enter` to type a value.
- **Presets** — `Enter` load · `n` new from the current look · `s` save over ·
  `e` rename · `d` delete. To edit a preset: load it, change what you like, save over it.
- **Palette** — the colors in use. `t` turns any palette into an editable custom one,
  then `a` adds, `Enter` edits and `d` deletes a color.

Presets live in `~/.config/termo/presets.json`. A preset you name `default` is
loaded automatically at start-up.

## Notes

- **"Full HD"** means full-HD *sources*: they are decoded and scaled down to your
  terminal grid. Resolution on screen is the grid × the mode's sub-cells
  (braille gives 2×4 dots per cell, sextants 2×3, quadrants 2×2, half blocks 1×2).
  Shrink the font for more detail.
- **Steady vs. shimmering dither:** ordered patterns (Bayer, blue noise, halftone…)
  are fixed to the screen, so they stay perfectly still on video. Error-diffusion
  kernels (Floyd–Steinberg, Atkinson…) look great on stills but shimmer in motion.
- **Sextants** need a font or terminal with the Unicode "Symbols for Legacy Computing"
  block (kitty, ghostty, wezterm and foot draw them natively).
- If sound and picture drift apart on your setup, nudge **Playback → Audio delay**
  (`--audio-delay`).

## Development

```sh
make test     # unit tests
make bench    # render benchmarks
```

The code is split into `internal/engine` (color, palettes, dithering, glyph
composition), `internal/tty` (diffing cell screen, key/mouse decoder),
`internal/media` (ffmpeg video/audio pipelines) and `internal/app` (player, HUD,
menus, presets).
